## 3. 数据与评估协议

使用公开验证集全部 15 个视频，0°/45°/90° 各 5 个；总帧数 2109。有效 GT 共 92 个，无效 GT 共 12 个。帧号采用 0 基索引，坐标是原图像素。此公开集用于当前评估，并已声明将用于参数选择；没有用它训练模型。

本地评分协议：`local_max_match_f1_frame1_px50_v1`。同视频的预测与有效 GT 同时满足帧差 ≤1、欧氏坐标距离 ≤50 px，才构成候选匹配；用最大基数一对一匹配确定 TP，不能让多个预测重复命中同一 GT。有效 GT 优先匹配；未匹配预测若在相同容差内接近 valid:false GT，则不计 FP。这里的无效事件忽略优先级为本地实现，官方处理可能不同。

注意：格式校验通过，只证明字段、范围、重复检查等合规，不能证明落点准确。当前评估的是触台帧号和坐标联合正确率，不是逐帧球定位 F1、bbox mAP 或单独的事件分类准确率。

## 4. 整体准确度与 F1 计算

| 指标 | 实测值 | 含义 |
|---|---:|---|
| TP | 61 | 正确匹配的落点 |
| FP | 42 | 未匹配且未被忽略的预测 |
| FN | 31 | 未被匹配的有效真实落点 |
| Ignored | 5 | 接近无效 GT，被本地协议忽略的预测 |
| Precision | 59.22% | 预测中有多少正确 |
| Recall | 66.30% | 有效 GT 中有多少被找到 |
| F1 overall | 62.56% | 合并全部 TP/FP/FN 后计算的 F1 |
| Macro F1 | 60.30% | 三个视角 F1 的简单平均 |

计数自洽：108 条预测 = 61 TP + 42 FP + 5 ignored；92 个有效 GT = 61 TP + 31 FN。

```text
Precision = TP / (TP + FP) = 61 / 103 = 59.22%
Recall    = TP / (TP + FN) = 61 / 92  = 66.30%
F1        = 2PR / (P+R)
          = 2TP / (2TP + FP + FN)
          = 122 / 195 = 62.56%
```

31/92=33.70% 的有效事件未被正确匹配；42/103=40.78% 的参与评分预测为误检。坐标错误或帧号错误可能同时形成一个 FP 和一个 FN，因此 FN 不等于完全没有输出候选，FP 也不一定全是球落地或击拍。

MIN_GAP 比较的是候选帧与“上一次实际输出”的间隔，不是与前一个 GT 的间隔。上一输出可能是误检，因此即使两个真实事件相距足够远，也可能因中间误输出而被过滤。反过来，小于 10 帧的 GT 对也不能直接证明本次 FN 都由该参数导致。由于未保存所有被拒候选及拒绝原因，当前只能提出假设，不能给出规则导致漏检的准确数量。
