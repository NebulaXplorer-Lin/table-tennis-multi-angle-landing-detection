# YOLO11n 球定位首轮测试

**结果：本轮权重尚不能用作可靠定位模型。只测试球定位，没有运行触桌判断。**

## 配置与完成情况

YOLO11n COCO 预训练 → ball 单类别，输入 640，FP32，AdamW，seed=42。3,162 张训练帧（原视频每 5 帧采样），5,302 张验证帧。先完成 64/32 样本的一轮 smoke，再执行上限 15 epoch 的正式实验。因连续 5 轮 mAP50–95 没有提升，第 6 轮 early stopping；best 来自第 1 轮。流程已完成，但这不表示模型充分收敛。

## 实际定位结果

| 指标 | 主评估 conf=.25 | 事后诊断 conf=.001 |
|---|---:|---:|
| 10px 球心 TP | 0 | 63 |
| FP | 0 | 6 |
| FN | 5,302 | 5,239 |
| Precision | 0（分母为零时的约定） | 0.913043 |
| Recall | 0 | 0.011882 |
| F1 | 0 | 0.023459 |
| 匹配误差中位数 / P90（原图 px） | — | 2.755 / 4.098 |

conf=.001 仍有 5,238 帧完全无输出，总计仅 69 个框；最高置信度为 0.039439。降低阈值无法消除严重漏检。误差仅对 63 个匹配框统计，覆盖率只有 1.19%，不能凭小误差认为总体定位良好。conf=.25 下有标注连续区间最长漏检 144 帧。

## AP 核对

框架报告 AP50=0.208536，AP50–95=0.066878，已保留原值。检查实际安装的 Ultralytics 8.3.225 `compute_ap` 后发现，它将 PR 曲线补到 (recall=1, precision=0) 并线性插值积分。在本轮极低召回下，未覆盖的召回区域也贡献了面积，不能把框架 AP50=20.85% 理解成能定位约两成球。

对事后单帧预测单独采用 101 个召回点、超过实际最大召回时精度置零的本地 AP 协议，AP50=0.009901，AP50–95=0.004257。这是另一评估记录，不是完整 pycocotools COCO 评分；单帧预测与 batch 验证也有数值差异，不能把两者的全部差值都归因于积分方式。同一份单帧预测使用库的线性插值可得到 AP50=0.170719，支持上述尾部积分问题。

## 速度与计算量

- RTX 5070 Ti / PyTorch CUDA FP32，batch=1，固定 1×3×640×640，前向 p50=1.655 ms、p95=1.677 ms。warmup 50，3×200 次 CUDA events。
- 六段完整验证视频，CPU 解码至 JSONL 写盘 E2E=316.73 FPS，实际预测为 stride 对齐的矩形输入。conf=.25 基本无检测框，后处理负担很轻，该速度不代表准确检测时的性能。
- 未融合模型 2.590035 M 参数，THOP 3.220301 GMAC / 6.440602 GFLOPs；不保证覆盖 functional attention 等操作。前向模型经过融合。

## 限制与下一步

只使用有球标注帧；2,844 个无球标注帧语义未知，未作为负样本，无法报告确定无球帧误报率。按场景保守分组，但缺少原始比赛来源元数据，不能证明完全独立。val 已用于 best checkpoint 选择，没有独立测试集。没有相同协议的热图对照，不能声称 YOLO 普遍无效或优于其他模型。

下一轮应先修正 best / early-stop 选择指标对低召回的敏感性，验证训练能稳定学习后再测试更高输入分辨率。此次没有继续启动新训练或自动调整部署阈值。未导出 ONNX/TensorRT；本机结果不代表赛事 4090。官方 pingpang 完整性校验通过。
