# 事件头改进建议（2026-10-18）

用户已确定：**桌框使用独立视觉分支，以桌框预测辅助任务监督特征；与球定位器的特征聚合后进入事件头**。训练仍按定位/特征提取、冻结前端训练事件头、少量训练数据端到端FT三阶段执行。桌框网络具体骨干尚未确定；本次没有实现或启动新训练。

建议先保留已验证的13帧TCN，优先改进**特征交互、运动可靠性、时间监督**。新方案均为待测假设，不预报提升幅度。

## 1. 当前代码和误差证据

- [ContextEventHead](../ttnet/src/models/event.py)将Global128+Local128归一化后投影到视觉96，运动9维投影32，旧桌框几何9维投影32，再融合到128；TCN为3个kernel3残差块，dilation1/2/3，最终读取中心时刻的128维表示。
- 最佳TCN三种子均值78.77%，Transformer为75.72%；EMA版本单seed42内部79.69%，但只比原TCN少一个FP，外部结果相同。
- [既有逐帧诊断](../out/results/20261017_4090_pretrain_review/diagnostics.json)：45个落点FN中，38个在GT±1帧已有有效且≤50px的球坐标；45处均无阈值/NMS后的事件峰。45处GT±1帧最大原始触台分数中位数为0.1099，22处低于0.1，35处低于0.2；只有4处在±5帧内有事件峰。
- 因此现阶段优先加强判别，单纯时间偏移回归或放宽NMS不能解释主要漏检。上述判断限定于当前内部标签协议，不说明未来新前端的误差仍然相同。

## 2. 首推：动态球特征与慢场景特征分开编码，学习交互

### 输入接口

每时刻保留三类信息：

1. 动态球信息：Global/Local视觉描述符、坐标/速度、可靠性信息。
2. 独立桌框分支：逐帧桌面视觉描述符、预测bbox、有效性、观测年龄及可获得的预测质量信息。
3. 相对关系：球相对桌框的位置、到边界的有符号距离、按稳定尺度归一化的运动。薄框分母设下限，缺失/异常值有mask，不能把空中球硬限制在框内。

三个视觉来源分别归一化和投影，避免新桌面描述符的数值尺度主导融合。首版可继续将球视觉压至96、运动32，桌面视觉增加32或64维，再统一投影到128；维度为候选设置，最终由配置记录。

### 融合方式

先建立“独立桌面特征简单拼接+原TCN”的匹配基线，然后测试门控残差/条件调制：

```text
球Global/Local视觉 + 运动 ── 动态表示 ── 条件融合 ── TCN ── 事件输出
独立桌面视觉 + 预测几何 ── 场景表示 ────────┘
```

场景分支根据桌面形态、球台相对位置与观测有效性，调节动态通道；可采用FiLM式通道缩放与偏置，残差调制从接近恒等变换开始。[FiLM原论文](https://arxiv.org/abs/1709.07871)提供条件仿射调制的方法依据，本项目收益需要独立验证。

- 硬mask处理真正无效的输入，学习门控处理有效但不可靠的输入。即使桌框或球坐标缺失，也保留其他视觉路径，不把最终触台概率整体乘成0。
- 对静态几何/场景身份可在同镜头内聚合，对桌面上球、人和遮挡形成的逐帧视觉变化仍可保留。不能因为桌子静止就将整个桌面视觉序列无条件平均成一个向量。
- 少量场景/Local分支dropout可作为后续正则对照，防止新分支成为单一捷径。训练/推理均只用预测桌框及约定的可用历史/窗口，镜头切换重置；不使用GT桌框聚合代替推理。
- 此阶段先只训练事件侧投影/融合/TCN，独立桌框与球定位器冻结。FT阶段再在线重算可求导视觉特征，并保留辅助定位监督。

## 3. 低成本方向：加强运动变化与观测质量表达

当前运动输入只有x/y、vx/vy、置信度和有效性等基础量。可在不增加原图前向的前提下补充：

- 事件时刻前后的平均速度、速度差、转向与有限差分加速度，按真实PTS计算，只在可靠连续观测上求差；不跨缺失、重捕获跳变或切镜头计算。
- Global/Local预测分歧、候选第一/第二峰分差、观测来源、距上次可靠观测的时间等。先使用实际缓存中可获得的量，不将检测峰值等同于经过校准的定位质量。
- 相对桌框的运动量使用稳定尺度和极值限制，避免侧视薄框将误差无限放大。

这些作为学习特征，不写“纵向速度反号就必定触台”等硬规则；击拍和错误关联也可能产生转向。采用有限幅度特征扰动/分支dropout模拟定位误差可后置，先保证质量mask与真实错误分布一致。

## 4. 时序结构优先做显式前后对比

原TCN中心表示**已经有13帧上下文**，并非只看中心图像。建议在相同窗口和未来帧预算下额外构造：

```text
h_center，masked_pool(h_before)，masked_pool(h_after)，h_after - h_before
                                  ↓
                            小型分类MLP
```

让输出层更容易比较触台前后的状态变化。空的前/后半窗显式mask，不用零值冒充有效观测；普通时间平均池化与质量加权池化分别做对照。

这个设计提供前后比较的归纳偏置，并不保证优于已有中心读出；预设比较须保持同一输入、TCN主干、监督和后处理。避免同时扩大窗口、加深骨干和增加读出结构。

多尺度时序、长短两路或更大的Transformer后置：已有seconds窗口整体替换的结果低于frames，不能未经对照再次用长物理窗口替换短时细节。若扩展窗口，未来等待、mask和真实时间跨度必须一起记录。

## 5. 单独验证粗时间标注的监督方式

新发现的具体差异：PP训练613个、验证203个事件均标为`coarse_manual`；[attach_pp](../ttnet/src/events/continuous.py)却只把指定原帧置1、其他已审核时刻置0。TTGames则由[prepare.py](../ttnet/src/events/prepare.py)按真实时间构造三角软标签。两源采样与时间口径不同。

首个低成本对照：保留PP硬事件GT、原采样中心和监督mask，仅将**训练目标**改为窄软峰，例如中心1、相邻原帧较低权重。邻帧强度/宽度作为预先固定的候选参数；这表达粗标签的不确定性，不把邻帧宣称为新增确认事件。

- 不把±1帧全置1；评价仍保持原GT、原帧±1/50px和一对一匹配。
- 缺失/unknown帧保持mask；GT附近软目标重叠时取最大值等合并策略需固定记录。
- 第一轮不同时改变PP正例比例、困难负样本占比或TTGames混合比例。已有20%正例/困难背景的配方退化到74.17%，不能把重做相同采样当作新方案。
- 不同目标会改变校准；各自仅在同一内部验证集选阈值，比较PR、三视角、TP/FP/FN和完整视频结果，外部测试不调参。
- 先检查PP粗时刻抽查质量，避免通过无界加宽标签掩盖真正漏检。全局平滑事件概率或直接套动作分割的平滑损失，可能抹平瞬时触台尖峰，不作为首轮主线。

## 6. 后续工程方向与最小实验顺序

当前对每个中心分别构造13帧窗口。冻结特征阶段可以研究带上下文的短片段、密集逐帧输出，以更好利用相邻已审核监督和减少重复计算，但这不自动带来精度收益。

若采用密集TCN，训练/推理片段边缘要提供与感受野匹配的halo或屏蔽边缘损失；TTGames稀疏未知时刻不能补成背景。当前相对中心时间编码随窗口中心变化，不能直接视作整段前向完全等价。该方向后置，不与首轮融合同时修改。

| 对照 | 主要变化 | 要回答的问题 |
|---|---|---|
| A | 新独立桌面特征简单拼接，原13帧TCN与原读出/监督 | 建立新前端下的事件头基线 |
| B | A + 场景条件门控/残差融合 | 是否更好利用桌面与运动关系？ |
| C | 当前验证胜者 + 前后状态读出 | 相同时间预算下是否改善触台判别？ |
| D | 当前验证胜者 + PP窄软目标 | 粗标注监督是否限制召回？ |

运动质量特征作为独立输入对照，不与上述所有改动一次合并。每一步无收益就回退，不必沿失败分支叠加；先seed42筛选，再对胜者补配对43/44。

候选选择以完整40视频宏F1与各视角P/R为主，观察是否追回“有球却未出事件”的FN，同时控制新增FP。新前端下重新做错误分解，不能沿用旧前端的38/45结论替代新评估。最终胜出的冻结版本保留，少量训练数据FT后再次比较。
