# 4090 完整训练前的优化建议（2026-10-17）

2026-10-18 更新：用户确定采用**先训练定位/特征提取 → 冻结前端训练事件头 → 少量训练数据端到端FT**。后续建议与实验均以此为准，不继续从第1轮全模块联合训练的路线。

建议优先推进**桌面区域视觉特征 + 门控融合**，先在冻结前端阶段验证信息价值，再进行小规模FT。现有证据更支持改进事件判别，而非继续扩大关联搜索或单纯延长训练。本次只检查现有代码、日志、预测与桌框叠图，未启动训练、修改模型或改变原实验状态。

桌框可视化见[检查说明](../result/scene_box/TABLE_REVIEW.md)，包含18组完整画面与局部放大、三视角对照和40个完整验证视频。

2026-10-18后续优先级更新：用户要求先提高桌框定位精度，再进行融合。先执行[桌框定位改进方案](table_localization_improvement_20261018.md)中的定位与数据覆盖改进；下面的桌面ROI/门控融合保留为桌框质量改善后的阶段2建议。

## 2. 首推：补充桌面区域视觉分支

当前 `ContextEventHead` 的桌框路径为：9 维场景输入 → MLP32 → 与视觉96、运动32拼接 → 投影128 → TCN。box 模式还屏蔽了球台相对位置；目前没有专门的桌面区域视觉描述符。

建议从 Global 已有的 32 通道 FPN 空间图采样桌面区域，保留原 Global / Local 分支：

```text
Global FPN ── 全图 2×2 池化 ── 原 Global 描述符 ────┐
           └─ 扩边桌框区域 4×4 采样 ── Table 描述符 ─┤
Local 球区域 ────────────────── 原 Local 描述符 ────┤→ 融合 → 原 TCN
预测运动 + 桌框几何 ────────────────────────────────┘
```

具体实施建议：

1. 对桌框做适度扩边，纵向设置最小像素范围，覆盖桌沿、网及近桌球轨迹。区域在 Global 特征图上采样，不增加独立大骨干；首版可用 4×4×32=512 维未投影特征，再由事件头学习投影到32或64维。
2. 先做简单拼接对照，再测试门控残差或 FiLM：用场景、运动与区域描述符产生通道调制，让桌框信息影响视觉/运动特征的处理。门控从接近恒等映射开始，减少新分支初期扰动。[FiLM 原论文](https://arxiv.org/abs/1709.07871)支持这种条件调制方法，但本项目收益仍需验证。
3. 无有效桌框时显式屏蔽区域分支；训练中加入少量桌框扰动、场景分支 dropout，保留原视觉路径作为回退。空中球可以在桌框外，避免把桌框当作全程球检测的硬裁剪或硬过滤范围。
4. 冻结前端阶段新增 ROI 特征缓存，缓存未投影的区域张量、mask、采样变换与身份哈希。当前已池化的4×4全图缓存不能恢复完整空间图，需要重新提取该区域特征。区域投影与融合层在事件头阶段训练。
5. 最后的FT阶段在线重算特征，可停止框坐标梯度，同时让区域视觉特征向 FPN 反传；桌框头继续接受桌框监督。不要直接沿用 NumPy/`detach()` 数据路径后声称事件损失已更新桌框头。

相关代码：[事件头](../ttnet/src/models/event.py)、[FPN 输出](../ttnet/src/models/localizer.py)、[联合训练](../ttnet/src/events/joint.py)。

## 3. 桌框几何需要增强鲁棒性

桌框整体验证 IoU 为38.75%。抽查三个视角叠图后能看到框范围与位置有明显偏差；不是只有逐帧抖动。按有标签验证帧重新聚合：

| 组 | 桌框平均 IoU | 预测高度/GT高度中位数 | 预测宽度/GT宽度中位数 |
|---|---:|---:|---:|
| 02 | 0.235 | 3.67 | 0.81 |
| 04 | 0.216 | 3.15 | 0.86 |
| 12 | 0.288 | 1.13 | 1.11 |
| 21 | 0.289 | 0.64 | 0.77 |
| 22 | 0.525 | 1.38 | 0.66 |

这些统计只覆盖有桌框标签的帧，02组仅46帧，不宜外推到该组所有画面。验证6292帧中有1191帧缺桌框标签；oracle 缺失也不能当成无桌。

当前 relative 的 `(ball_y-cy)/table_height` 会放大侧视薄桌框误差。建议：

- 对归一化分母设下限，并对极值做截断；保留宽高、长宽比和有效性信息，让网络识别薄桌面情况。
- 加入球到四条框边的有符号距离、按稳定参考尺度归一化的速度，以及真实 Δt。先作为低成本对照，不直接替换成此前已退化的原 relative。
- 当前 TableHead **没有校准质量分数**；几何有效不代表准确。可先用 mask、时序一致性和学习门控，若增加质量头则用训练标签监督 IoU/质量，并在验证集检查校准。
- 桌框头训练和模型选择按视角检查薄框的高度/中心偏差；若投入更强 ROI 融合，应重新评估桌框预测，而非沿用“桌框质量不是瓶颈”的结论。

现有 bbox 不提供真实桌角或桌面四边形；直接拿矩形四角做单应不能恢复真实桌面。四角/分割可以作为后续方向，但需要可靠监督来源与额外验证。

## 4. 已确定的三阶段训练路线

**阶段1：训练定位与特征提取。** 在固定训练视频上训练Global/Local定位器与桌框头；特征提取器接受定位/桌框监督。先检查球定位、ROI含球率、桌框IoU及三视角误差。Local可用GT+jitter裁剪启动，但结束前要适应预测ROI。此阶段不接入事件损失，不同时调事件头。

**阶段2：冻结前端，提取特征并训练事件头。** 用预测轨迹、预测桌框和与推理一致的连续追踪生成缓存。缓存Global/Local描述符、桌面ROI未投影张量、运动/几何、mask、真实PTS、ROI变换和前端权重身份。只更新事件投影、融合与TCN；桌面ROI和门控的主要消融在本阶段完成。选择最好的事件头后保留完整冻结版作为FT回退基线。

**阶段3：使用少量训练数据做端到端FT。** 从原训练集固定选取覆盖三视角的少量完整视频/片段，同时保留普通背景、正确事件、困难背景和定位困难例；不只选高置信成功样本或错误样本。记录子集清单、来源和哈希，不从验证集采样。

- 从阶段1/2的权重开始，少轮数、小学习率微调；视觉编码器学习率低于事件头，保留定位与桌框辅助损失，防止事件收益伴随定位退化。具体子集比例、轮数和学习率尚未指定，执行前固化为独立配置。
- FT必须在线重算可求导视觉特征，不能继续使用冻结的NumPy描述符缓存。缓存只能复用原始图像等不依赖更新权重的数据。硬候选选择和ROI坐标可沿用现有处理，事件梯度经视觉描述符更新编码器。
- 如果FT使用短窗口，加入足够历史或按顺序处理片段，减少与完整视频连续追踪的状态差异；验证始终按同一40视频完整推理。
- 同时监控落点宏F1、各视角P/R、球定位与桌框质量；未改善则保留阶段2权重，不因FT更新了更多模块而默认选FT版。FT后的阈值仍只在内部验证选择。
- 补充真实的验证定位指标和桌框指标。当前关联运行时返回的Global/Local loss=0是占位值，不能解释成定位验证损失已降到0；Table验证损失也缺失。
- 图像增强在阶段1与FT在线路径使用，并保持整窗口一致；球、桌框、ROI、运动与坐标变换必须同步。
- 内部坐标是事件帧球心参考，public为实际接触点；没有真实接触点监督时，不把球心直接当作真实接触点偏移回归标签。

历史全随机初始化联合训练作为已停止的独立实验保留，不作为下一次训练入口。

## 5. 4090 前必须处理的工程项

1. 比赛文档固定 torch2.1.2，本地依赖是2.7.1。`events/train.py`、`events/scratch.py`、`training/train.py` 使用了新命名空间 `torch.amp.GradScaler(...)`；迁移时应适配比赛版本的 `torch.cuda.amp.GradScaler(...)`，在原镜像做前后向与恢复检查，不升级比赛基础组件。[PyTorch 2.1 AMP 文档](https://docs.pytorch.org/docs/2.1/amp.html)
2. 阶段1的定位训练与阶段2的冻结特征提取优先采用批处理；事件头训练可复用身份一致的缓存。阶段3再优化在线路径的读图、归一化、候选处理与GPU→CPU同步。现有在线配置 `joint_frame_batch=2` 可通过小规模测速调整，保持effective batch不变，先确认数值与训练语义一致。
3. 新增区域采样应尽早验证 ONNX/实际 TensorRT8.6 后端支持及数值一致性。50FPS是评分封顶，新增分支的完整视频吞吐必须在比赛镜像与4090实测；本地5070Ti成绩不能代替。
4. 若有两张4090，可优先分别跑对照/不同种子。当前代码不能仅凭可见两卡就认为已完成数据并行支持。

## 6. 建议的最小实验顺序

| 顺序 | 方案 | 要回答的问题 |
|---|---|---|
| A | 当前TCN+box+时间编码+EMA | 固定回退基线 |
| B | A + 桌面ROI视觉，简单拼接 | 桌面区域是否提供额外有效信息？ |
| C | B + 门控残差/FiLM | 条件融合是否优于简单拼接？ |
| D | 阶段2选中的权重 + 少量训练数据端到端FT | 小规模FT能否继续提升，同时保住定位与桌框质量？ |

B/C先用冻结前端筛选，比较同一划分、采样、种子与后处理；候选胜出后再补配对seed43/44。桌框头改进在阶段1评估，区域视觉与融合在阶段2评估，少量数据FT作为阶段3单独对照。

每组关注40视频宏F1、三视角P/R/F1、FN变化与FP新增，尤其当前diagonal约74.51%、front召回75%。阈值各自在内部验证集选择，不能只比较相同数字阈值。外部结果已被历史查看过，冻结选型后再报告，不用来反复迭代。

AR扩大beam、直接换Transformer、重复此前正例/困难背景采样配方，均已有负结果，本轮优先级低。多尺度时间分支可后置；此前seconds版已退化，不能无对照地重新替换原生13帧窗口。
