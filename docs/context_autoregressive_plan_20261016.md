# 场景位置特征、自回归轨迹与事件头实验方案

日期：2026-10-16（Asia/Shanghai）。本次为现有结果、代码与原始标注核查及方案设计；未实现新模型、未启动训练，下面的新方案均未测得增益。

## 1. 当前实验支持什么

固定 PP 114/40 视频训练/验证划分、seed42；Global/Local 定位器冻结。实际完整视频结果见 [现有实验汇总](experiment_comparison_20261016.md)，数据和训练偏差见 [进一步核查](next_stage_validation_20261016.md)。

| 方案 | 定位/关联 | 事件头 | 验证落点三视角宏F1 |
|---|---|---|---:|
| A | 独立定位 | TCN | 72.44% |
| B | 多候选规则关联 | TCN | 77.96% |
| C | 独立定位 | Transformer | 55.85% |
| D | 多候选规则关联 | Transformer | 65.63% |

B 本机完整视频 86.54 FPS，TP/FP/FN=148/41/41；实际 metrics.json 已核对。结果只支持当前验证协议下的优势，多种子及本轮模型外部测试未完成。B 相对 A 还改变了 Local ROI 数与提议门槛，因此不能将全部提升归因于 beam search。

轨迹关联将球心 F1@10px 从85.08%提高到87.79%，但最长漏检仍22帧，漏检段P90由3变5；持续跟错值得专门处理。Top5候选oracle的10px命中率90.44%表明候选排序有空间，但不是最终模型保证达到的精度。

TCN 与 Transformer 输入融合不同：前者视觉256→96、运动9→32，后者265→128直接投影再加时间编码。当前不是纯粹卷积/注意力对比。C连续触台漏检106/203，时间容差放宽到±5帧仍只命中97个，优先检查特征使用和监督，不能只增加时间偏移回归。

## 2. 球桌和球员框：复用标注，先做几何特征

本次直接遍历 `data/pp_train_data/annotations/**/*.json` 的154份原始JSON，统计的是标注帧记录，不是全部视频解码帧：

| 标签 | 有标签的帧记录 | 框数 | 覆盖视频 |
|---|---:|---:|---:|
| table | 22,382 / 23,690 | 22,382 | 153 / 154 |
| player | 23,673 / 23,690 | 52,452 | 154 / 154 |

player数量分布：0框17帧、1框3091帧、2框15251帧、3框2600帧、4框2602帧、5框123帧、6框6帧。尚未逐帧人工核验框质量；框多于2不能直接判断为误标，也不能按JSON顺序认定对打球员身份。

### 数据与推理接口

- 保留原始 `bbox_xyxy`、原图宽高、帧号和时间戳；归一化与裁剪使用统一坐标变换。
- 场景数据独立保存为 `scene_context`：桌框、可变数量player框、各框valid/confidence/source、跟踪ID（若可靠）和观测距当前时间。缺失使用mask，不能以零坐标冒充真实位置。
- 训练监督可用人工框；正式完整视频推理使用检测框。人工桌/球员框的验证实验只作为oracle上限，单列结果。若产品明确依赖用户手选初始桌框，则作为另一种带人工初始化的协议。
- 桌框可在固定镜头下低频更新，但只有经稳定性检查才沿用历史框；镜头变化重置。球员框需随时间更新，低频检测＋跟踪的频率按速度/误差实测确定。
- 检测器只用既有训练视频训练，保留114/40划分。先审查缺标和框语义，再生成检测训练集；缺标不直接当确定负样本。TTGames没有同格式框时，用同一检测器生成或显式mask，不填人工猜测值。

### 第一版特征

保留现有256维视觉和9维运动输入，新增独立场景分支，建议先输出32维嵌入：

1. 桌框：归一化中心与宽高、球相对桌框的x/y、距四边的有符号距离、球是否落在框内及valid/confidence。相对坐标可越界，不能把球硬裁进桌框。
2. 球员集合：每人框中心/宽高、球到框的相对位置和最短距离、球员位移/真实Δt、valid/confidence；共享MLP后做带mask的集合汇聚。第一版不强行选择两个人，避免引入身份跳变；需要身份时另做主赛球员选择和跟踪验证。
3. 分开编码桌面和球员，再与视觉/运动融合；两种事件头共用同一融合模块。几何特征有效后，再比较球员ROI外观或姿态，避免一次引入多个变量。

桌框提供粗场景参考，不能代替桌面四角和单应标定；球在框内也不等于触台，球飞行阶段不能强制满足桌面二维物理约束。

### 接入位置

- `events/data.py::assemble_window`：添加独立场景张量与mask，不偷偷改变现有9维motion语义。
- `models/event.py`：共享融合前端，新增可配置场景输入；保留旧模型加载和无场景基线。
- `events/engine.py::cache_identity`：增加场景schema、标注或检测器权重哈希、框来源、关联配置及特征代码身份，防止复用旧缓存。
- `events/batched_features.py`、`events/context.py`、`events/inference.py`：保证训练缓存和原视频推理使用一致的框来源、时间对齐和缺失规则。

## 3. 用学习式自回归评分替换手工轨迹代价

`tracking/association.py::BeamTracker` 已有Top5、beam_size=8和missing分支。当前代价含负log置信度、恒速外推距离、RGB均值外观距离、固定missing代价；`tracking/runtime.py` 内另有Local候选手工排序。替换时两处都需覆盖，不能仅替换一个评分函数就称全链路学习式关联。

建议第一版保留定位器，用小型GRU做候选选择的自回归解码器；模型类型与事件头TCN/Transformer是两项独立设计。先学习候选关联，再考虑自由生成坐标或联合微调定位器。

设 C_t 为本帧候选集合，s_t 为桌/球员上下文，z_t 为候选索引或空观测：

`p(z_t | z_<t, C_<=t, s_<=t, Δt)`

- 候选编码输入坐标、检测置信度、候选局部外观、相对桌面/球员几何；decoder隐藏状态编码历史所选候选与缺失状态。置信度成为模型输入，不再固定乘手设运动权重。
- 所有有效候选与空观测一起softmax，使用统一的条件概率；beam以累计log概率排序，同帧路径长度一致，保留各自隐藏状态。beam宽度先对照1/4/8。
- 空观测只表示当前没有可接受观测，不宣称物理上无球。已知球心而候选全未命中时可以监督空观测；unknown帧屏蔽该帧选择损失，不自动生成无球标签。
- 已知球心对应候选集合内距离合格的候选；多个候选合格时使用集合概率质量损失，避免任意索引唯一化。匹配容差预先固定并记录，和最终10px/50px评分分开。
- 初期teacher forcing，随后比较预测历史rollout训练；训练序列包含遮挡、误选恢复、触台和快速变向。模型历史不得使用未来真值，验证不能注入GT路径。
- 可增设下一位置分布预测，用于候选ROI提议。其预测均值不直接充作可见球观测；不要仅用MSE逼模型在反弹/遮挡处平均多种可能运动。
- 原始图像的三帧定位器使用t+1，因此“关联因果”不等于整套系统零前视；保留现有前视预算并记录真实延迟。

### 搜索与计算预算

现有实现每帧输出当前最佳路径的当帧选择，之后不会修正已输出历史。新增模型先复用这一模式；固定延迟回溯应作为另一实验，与即时提交分开。否则扩大beam也不保证早期已输出错误能被纠正。

beam是近似搜索，宽度增加并不保证真实F1提高；重点比较学习式greedy与学习式beam，区分模型与搜索收益。保留全局重捕获候选，避免历史漂移后无法返回。多路径不能各自无限增加Local ROI：第一轮固定与B相同的每帧2个ROI预算。学习式ROI提议若改变候选集，另开消融。

只更换候选选择不能恢复候选集合外的球；因此同时报告候选覆盖上限、所选命中率、持续跟错长度和端到端落点。离散TopK/裁剪/beam并不自动可微，第一版采用分阶段训练，后续联合训练需明确梯度路径。

自回归视觉跟踪的相关方法可参考 [SeqTrack（CVPR 2023，作者论文）](https://openaccess.thecvf.com/content/CVPR2023/html/Chen_SeqTrack_Sequence_to_Sequence_Learning_for_Visual_Object_Tracking_CVPR_2023_paper.html)。其框坐标序列生成提供方法参考；本方案是跨帧候选选择，不能直接套用该论文的增益或声称复现。

## 4. TCN / Transformer受控对比

先固定B的预测轨迹与视觉缓存，不同时更新关联器：

1. 共同前端：视觉256→96，运动9→32，场景可选→32，再投影到统一隐藏维度128；共同的归一化、缺失mask和中心帧分类头。
2. 第一组保持13原始帧，使用相同真实时间信息，只替换时间卷积/自注意力；相同数据、seed、采样、训练预算、早停与阈值选择协议。报告参数量差异；再做近似等参数对照，不能把同隐藏维度称作等容量。
3. 时间编码作为显式消融，分别比较有/无额外时间编码；motion内已有真实时间，不将移除额外编码写成完全不使用时间。
4. 另比较固定物理时长窗口：现有13帧在25/30/60FPS下跨度0.48/0.40/0.20秒。按真实PTS选帧并保存原帧映射，重复/缺失采样有mask；评估仍按原视频±1帧。长窗口需同时扩大TCN有效感受野，否则比较不公平。
5. PP与TTGames来源各50%并非正样本平衡：现有seed42第一轮PP正目标122/3867，TTGames568/3867。单独消融PP事件附近采样和困难背景；两种头共享修改，完整视频保留真实负样本分布用于验证。
6. 完成共同配方后，给两种架构相同调参预算做各自优化；这组与“相同超参”组分开报告。最终候选至少seed42/43/44，报告均值/波动、逐视角和逐比赛组。

## 5. 实验顺序与验收

| 阶段 | 对照 | 要回答的问题 |
|---|---|---|
| E0 | 补A/B多种子、冻结现有身份 | B收益是否稳定 |
| E1 | B / B+桌框 / B+player / B+两者，固定TCN | 哪种场景信息有效；人工框oracle与预测框实用收益有多大差距 |
| E2 | 相同候选/ROI预算下，规则beam / 学习式greedy / 学习式beam | 学习式评分和搜索分别是否有益；先固定同一事件头诊断，再各自重训事件头比较可达到的效果 |
| E3 | 固定胜出的轨迹、场景、融合前端，TCN / Transformer | 时间建模结构本身是否造成差距 |
| E4 | 锁定配置的外部测试和完整视频测速 | 收益是否迁移，新增检测与搜索开销是否可接受 |

E1先用人工框诊断有无场景信息价值；人工框无明显收益时先查表示和标注，不直接投入大检测器。E1正式方案必须补预测框结果，并用预测框/噪声/缺失训练减轻训练推理差异。较严格的预测特征可在现有train内部折外生成，不能变动外层val清单。

主指标仍为原帧±1、原图50px的一对一落点三视角宏F1；同时看时间触台P/R、球心F1@10/50、最长漏检/跟错、逐组差异和原视频错误叠加。桌/球员检测、解码、关联、事件头都纳入完整视频FPS，另报前视等待和p95延迟。历史public已被查看过，应称外部迁移对照，不称从未使用的盲测集。

优先交付顺序：**场景数据与特征接口 → 场景消融 → 学习式候选关联 → 同前端事件头比较**。每一步保留旧基线和独立配置；不一次性合并全部改变后只报一个分数。
