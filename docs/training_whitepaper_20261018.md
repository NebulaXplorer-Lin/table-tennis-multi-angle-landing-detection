# 乒乓球落点检测训练白皮书

4090训练方案与数据准备

版本 1.0　日期 2026年10月18日　适用仓库 pingpong

部署约束更新：服务器磁盘仅100GB总容量，本次迁移改用[原视频按需解码方案](server_100gb_20261018.md)，关闭磁盘图像缓存。本文第4节的233GiB缓存迁移和第10至11节基于该缓存的排期保留为历史参考；当前训练耗时须按无磁盘图像缓存路径重新测定，训练任务与标签协议仍适用。

本白皮书将后续训练收敛到一条可执行路线：先完成球定位和独立桌框分支，以预测任务监督视觉特征；冻结前端后训练事件头；最后仅使用原训练集中的少量数据进行端到端微调。完整视频的落点宏F1、三视角表现与部署速度共同决定最终版本。

正文中的“现有结果”来自本地实验产物；“建议起点”是待验证配置；“耗时预算”是排期估算。新独立桌框分支、特征缓存接口与少量数据微调流程尚需工程实现。本次交付为训练方案，没有启动训练或修改模型行为。

## 1 已确定的路线与训练范围

| 阶段 | 训练对象与输入 | 进入下一阶段的产物 |
| --- | --- | --- |
| 一 定位与特征提取 | Global和Local球定位；独立单帧桌框网络，以桌框预测监督其特征 | 球定位与桌框权重、完整视频评估、统一坐标接口 |
| 二 冻结前端训练事件头 | 预测轨迹、球视觉、独立桌面视觉、几何、真实时间与有效性mask | 冻结版事件模型、受控消融、固定验证选型 |
| 三 少量数据端到端微调 | 从前两阶段权重初始化，在线重算特征，保留定位与桌框辅助损失 | 与冻结版比较后的最终权重及部署包 |

桌框分支不复用球定位器的编码器。单帧定位与镜头内稳定聚合可以结合，但不能无条件把整个视频视为固定桌框。具体桌框骨干尚未确定；本白皮书用预训练YOLO11s、640输入作为首个工程参考方案与预算参照。

阅读顺序：数据准备见第3至4节，训练与增强见第5至9节，4090耗时与任务安排见第10至12节，验收和证据见第13至14节。

建议为单张4090预留一次完整训练夜间窗口：**重训Global和Local约6–13小时；复用合格定位器约4–10小时**。该预算包括桌框训练、一次特征提取、事件头筛选、一次少量微调及最终检查，前提是数据已就绪、代码已通过预检、使用每轮4000张的桌框轮换采样方案。它不包含人工改标、功能开发和上传时间，也不是4090实测承诺。

优先解决四件事：复核桌框错标并冻结版本；训练独立桌框分支；建立新前端下的简单拼接TCN基线；分别验证门控与监督改进。定位器、事件头、数据配方同时大改会使结果难以归因。

| 现有证据 | 结果 | 对训练任务的含义 |

| 旧桌框头 last 第14轮 | 训练0.7994，验证0.3007 | 单纯增加训练轮数缺乏依据 |

| 原TCN加桌框与时间编码 | 宏F1 79.56%，144 TP、34 FP、45 FN | 作为新实验的历史参照 |

旧TCN的45个FN中，有38个在GT前后1帧内已经存在距离事件参考位置不超过50px的预测球坐标。这提示事件判别值得优先改进。该统计利用GT检索邻域，仅用于错误诊断，不能解释成可部署的召回上限；更换前端后需要重新统计。

旧几何消融中，预测relative为78.34%，人工桌框的oracle-relative为79.04%，同模式差约0.70个百分点。不能拿oracle-relative与box模式的差值直接归因于框精度，也不能据此否定独立桌面视觉的潜在价值。

桌框标签审计显示，125/153个有标签视频的逐视频GT中位框参考平均IoU达到0.95；同时存在15_002的构图变化、13_007的平移变化和08_004的近景切全景。04_004第115帧的桌框明确落在地板，115–120帧应优先人工复核。GT中位框是诊断工具，不是部署预测，也不应自动覆盖原标注。

本轮不优先推进更大的Transformer、扩展AR beam、重复此前退化的20%正例加困难背景配方，或继续全随机联合训练。已有负结果只约束当前配置，不能推出这些方法在所有条件下无效。

PP固定划分按源场景组隔离，训练19组、验证6组。继续复用实际清单和哈希，不因模型、种子、采样或增强变化而重新划分。OpenTTGames也不按帧随机切分。相邻帧、增强副本和同源片段必须留在同一集合。

OpenTTGames训练原始锚点3352个，其中Bounce 1289、Net 986、empty 1077；验证450、测试464个。移位后训练窗口12452、验证2178、测试2144，这些窗口并非独立事件。稀疏锚点外的未知时刻不能补为背景。

PP事件的空间参考是事件帧球心，public标注是真实接触点。两者不能直接混作接触点偏移回归监督。PP未单独审核Net的区域继续屏蔽Net损失，不能从“只有Bounce标注”推断“没有Net”。

内部落点空间匹配使用189个有效空间事件；14个缺坐标事件不进入空间TP和FN，其前后1帧可吸收尚未匹配的预测，避免将其误判为空间FP。纯时间诊断仍使用203个事件。此口径来自现有评估代码，后续不能无记录更换。

PP保留原生帧号及实际帧率。OpenTTGames按真实PTS从120fps选最近原帧形成25fps采样，不用插帧伪造观测。事件头保留13原生帧和真实时间偏移；不同帧率下物理跨度不同，必须在日志中可见。

预处理必须验证解码尺寸、标注尺寸、帧号基准和PTS。当前PP包括1280×720、1266×720与1920×1080，不能将所有720p强行视为1280宽，也不能用缩放后的像素误差代替原图50px容差。

## 4 数据准备与版本冻结

按以下顺序准备数据，完成后再启动正式训练。

1. 冻结原始视频、标注、现有train和val清单，记录文件哈希与转换脚本版本；抽查重复文件及同源跨集合情况。
2. 建立桌框复核清单，优先检查04_004第115–120帧、薄框、异常高度、主球台选错、镜头变化和长段缺失。人工确认修正，无法可靠修正时标unknown；保留原值、修订值、原因和审核人。
3. 如修订标签，建立新版本及patch ledger；旧标签保留。用同一新版本重新评估旧桌框头和新模型，不能只修正某个模型的不利样本。训练数据版本变化后，重建相关target与采样清单。
4. 导出逐帧统一记录：视频、source_group、split、原帧号、PTS、原尺寸、ball状态及球心、table状态及bbox、event类别与mask、标签来源和版本。
5. 先验证坐标往返，再查看三视角随机样本及全部异常样本的GT overlay；为缩放、letterbox、翻转、裁剪和反投影保存统一变换矩阵。
6. 预检小批次读图、增强、前后向、断点恢复和完整视频推理；所有阶段使用同一标签语义与坐标约定。

旧桌框target的坐标往返误差约0.000052px，说明该编码链路未见数十像素系统偏差；这不能替代对标签内容的人工复核。现有标注是轴对齐bbox，不能把其四角当成真实桌面四角去求单应。

### 存储与迁移

当前FrameStore是RGB uint8、每块32帧的mmap NPY。PP缓存23690帧，实际NPY约65.59GiB；OpenTTGames缓存28883帧，约167.34GiB，合计232.92GiB。后者是现有准备范围，不能代表OpenTTGames全部原始长视频已缓存。

建议比赛机使用本地SSD，迁移前核对manifest和分块哈希；为这两套缓存及新特征、权重、解码临时文件至少预留350GiB，包含原视频与额外resize缓存时建议500GiB可用空间，实际以待传文件清单为准。不要沿用历史PNG的19.3GB统计，也不要无意同时保留两套展开缓存。

232.92GiB原样传输，在持续1Gbit/s时理论约33分钟，100Mbit/s约5.6小时；均不含协议损耗。若带宽有限，可传原视频、标签和manifest后在比赛机重建，需另测解码耗时并核对像素身份。数据上传与重建单列，不计入后文训练预算。

## 5 阶段一训练定位与独立桌框分支

### 球定位

Global和Local延续现有fixed3配置，首轮不同时改变时间输入、关联策略和输入尺度。建议参考20轮、AdamW学习率3e-4、effective batch 8、AMP；micro batch从2开始，显存允许再调整并保持effective batch不变。最终配置以现有运行文件核对后的快照为准。

Local可按现有课程从GT加抖动ROI启动，逐步转为预测ROI；例如前10轮完成过渡，最后阶段完全依赖预测裁剪。GT只用于训练裁剪与辅助监督，验证始终运行预测轨迹。已知球落在当前ROI外可作为该ROI的局部空目标，不能推广成原图未知帧等于无球。

已有定位器若身份、数据版本与完整视频精度合格，可以复用；若重训则先Global、后重建Local所需预测、再Local。不要因“完整训练”而抛弃合格权重，也不要跳过复用权重的数据身份核查。

### 独立桌框网络

建议起点为预训练YOLO11s、主比赛球台单类、640输入，保留空间特征至预测头；桌框监督更新独立编码器。YOLO11的训练与导出能力见[官方文档](https://docs.ultralytics.com/models/yolo11/)，具体权重、版本、许可与比赛环境兼容性在实施时固定。

建议50–80轮，batch 16起测，AMP；预训练骨干学习率1e-4、检测头1e-3作为AdamW分组起点，warmup 3轮、余弦衰减、weight decay 1e-4。该配置需要实现并验证参数分组，不能与框架默认优化器设置混用后仍声称相同配方。

每轮约4000张，按训练场景组、视频、时间位置与薄框桶分配，跨轮轮换覆盖全部可靠训练帧；不是永久只保留4000张。薄框样本的采样概率首轮最多提升到普通样本的3倍，记录实际分布。80轮320000次曝光约等于18.5次全量训练帧曝光；轮数不能直接与全帧80轮比较。验证覆盖完整40视频，不做训练增强。

检测后必须用确定规则选择主球台，不能用GT选预测。监督缺失的图片不可输出空label当作无桌负样本；无可靠主球台标注则从桌框监督中排除，但保留其用于其他已知任务。类别分数也不等于校准过的IoU质量。

进入阶段二前，报告帧均和视频均IoU、三视角与源组结果、薄框上下边误差、漏检和主球台选错率，并输出错误overlay。平均IoU约0.70可作为初始工程目标，尚无保证；未达目标时先查残余错误，再单独比较960输入或模型调整。

## 6 数据增强的分阶段做法

所有范围均需写入配置。下表区分已有实现与待验证建议；先使用温和方案，再一次只增加一种增强。

| 适用阶段 | 操作 | 建议参数与状态 |
| --- | --- | --- |
| 球定位 | 水平翻转 | 概率0.5，已有实现；球心、热图与坐标同步 |
| 球定位 | 亮度与曝光 | scale 0.85–1.15，offset −8至8，已有实现 |
| Local | GT裁剪抖动 | 裁剪边长的0.2范围，已有实现；后期转预测ROI |
| 独立桌框 | 几何变化 | 翻转0.5；平移各轴±5%，scale 0.9–1.1；建议起点 |
| 独立桌框 | 轻微旋转 | ±2度，建议起点；变换四个角后重算轴对齐外接框 |
| 在线图像路径 | 成像退化 | 概率0.1–0.2，单独比较轻模糊、轻噪声或压缩 |
| 冻结事件头 | 特征鲁棒性 | 可单独测试分支dropout 0.05–0.1，显式mask；尚未实现 |
| 少量微调 | 温和增强 | 以已验证翻转、曝光为主；降低几何扰动，保持窗口一致 |

在当前BallDataset中，三帧图像共享同一次翻转、亮度scale与offset；扩展到13帧和桌框分支后继续保持同一时序窗口参数一致。逐帧随机亮度或几何扰动会制造假运动。增强后需要重新计算球心、bbox、ROI、速度及几何特征，不能只改图像。

建议的成像退化候选为3×3轻高斯模糊、像素标准差2–4的噪声、JPEG质量80–95，概率与强度分别记录；这些尚未实现，也不同时全部开启。抽查增强后小球仍可辨识，不能将被增强抹掉的小球继续当作可靠可见正例。不要把120到25fps抽帧等同于运动模糊模拟。

框经过几何变换后必须检查裁剪、可见性和退化面积。未知区域保持unknown；随意裁掉球或桌边后不能保留原坐标。首轮关闭垂直翻转、强透视、Mosaic和MixUp，避免破坏比赛几何与主球台语义。增强机制参考[Ultralytics官方说明](https://docs.ultralytics.com/guides/yolo-data-augmentation/)，本项目参数是待验证建议，不是官方推荐值。

冻结描述符不能通过“翻转向量”精确模拟图像翻转。若阶段二需要图像增强，应由冻结前端在线提取，或预先生成带变换身份的增强特征视图，并单列缓存成本。普通特征噪声、dropout仅代表另一种正则化。

首轮不做时间反转或任意丢帧。后续若验证时间重采样，应保留真实PTS、原帧映射及缺帧mask，维持训练监督语义；评估仍使用原帧号和原容差。

## 7 特征提取与事件输入接口

阶段二冻结Global、Local和独立桌框编码器，用与推理一致的预测轨迹和预测框生成特征。验证不能借用GT ROI、GT桌框或GT事件位置。训练缓存同样优先使用预测前端，减少训练与部署分布差异。

| 输入分支 | 建议保留的信息 | 接口要求 |
| --- | --- | --- |
| Global与Local | 原有视觉描述符、球心候选与关联结果 | 权重固定，禁止把GT填入预测轨迹 |
| 桌面视觉 | 独立编码器的桌面区域特征及上下文描述符 | 保留投影前特征，事件投影在阶段二训练 |
| 几何与运动 | bbox、球相对位置、速度、真实Δt | 原图坐标可还原，分母下限与截断规则固定 |
| 质量与缺失 | 有效mask、ROI内球置信度、缺失长度、框年龄 | 缺失显式编码，不用零坐标冒充有效观测 |

首版桌面视觉可从预测框适度扩边的区域取4×4空间池化特征，再投影到32或64维。全图上下文可另外保留；不必先做高维ROI再把投影固定死。空间采样、最小ROI高度和框扩边比例在配置中固定，确保薄框仍覆盖桌沿和网。

桌框几何和静态场景描述符可以在稳定镜头内低频更新，0.2–0.5秒可作为后续对照起点。动态桌面视觉首版逐帧提取，避免直接平均掉触台瞬间的视觉差异。若需要低频复用整条桌面分支，应单独验证事件F1与速度；桌框静止不等于ROI内图像静止。

镜头切换、明显平移缩放、质量下降或历史过期时重置聚合。聚合只能基于已到达的预测，不能使用整段GT中位框，也不能不计未来等待。验证从视频开始连续追踪；训练短窗口需要足够历史或按顺序片段预热，记录与连续运行的状态差异。

每份特征manifest至少包含数据及标签版本、split、原帧与PTS、图像变换、前端权重SHA256、关联配置、桌框选择与更新策略、特征shape与dtype、代码版本。只要权重或生成规则变化，生成新cache_id；同一前端的A至D消融才可复用缓存。

现有两套原帧缓存合计52573帧，其中训练38447、内部验证9980、TT测试4146。它们可用于估算当前特征重提取量，但实际连续追踪可能需要额外前驱与间隔解码；实施时从任务清单核实总量。更长的原始视频全面重提取另行计费。

## 8 阶段二事件头训练与消融

保留13原生帧、真实PTS编码和原TCN作为主线，先建立新前端下的简单拼接基线。不同分支先做归一化与独立投影，再进入融合层，避免桌面特征的量纲与维度压倒原球视觉分支。

| 编号 | 单次主要改动 | 需要回答的问题 |
| --- | --- | --- |
| A | 独立桌面视觉与原球视觉简单拼接，原TCN | 新前端的可靠基线是什么 |
| B | A加场景条件门控或残差FiLM | 条件融合是否优于拼接 |
| C | 当前胜者加中心、前后池化及前后差读出 | 是否改善触台前后状态比较 |
| D | 当前胜者仅调整PP训练目标为窄软峰 | 粗时刻监督是否限制召回 |
| Q 可选 | 单独加入运动质量与缺失特征 | 质量信息是否减少假轨迹误报 |

B的门控从接近恒等映射初始化，并保留原视觉路径。C保持同一窗口与未来帧预算，前后池化对无效帧做mask；空半窗不得当作有效零观测。B与C没有收益则回退，不沿失败结构继续叠加。

D保留原PP硬GT、采样中心与监督mask，只改变训练target。建议预先固定两种窄峰候选：中心1，相邻原帧0.3或0.5；未知邻帧继续屏蔽，重叠软峰取最大值。不要把前后1帧全置1。评价依旧原GT、±1帧、50px和一对一匹配；PP软目标与TTGames按PTS构造的三角软目标分别记录。

建议起点：AdamW学习率3e-4、dropout 0.1、effective batch 8、最多40轮、patience 8；延续当前PP和TTGames各50%、每轮7734窗口。保持采样与后处理口径不变，首轮不同时提高正例或困难背景比例。具体参数要在运行前形成实际config，而不是依赖本表自动生效。

先seed42依次筛选A至D，对最终候选与A补配对seed43、44。每个配置在同一内部验证集按固定规则选阈值，报告配对差值、三视角P/R/F1与TP/FP/FN；单次0.1个百分点变化不足以证明稳定收益。public和TT测试在选型冻结后统一检查。

冻结阶段每轮在40条验证视频的全部缓存帧上运行事件头和连续后处理，不能只评估稀疏事件锚点。缓存前端已经完整连续处理原视频，入围版本再从原视频重放核对在线一致性并输出overlay。后文的事件头预算基于这一方式；若每轮都重跑原视频前端，需另加对应成本。微调阶段前端变化，每轮必须重新在线验证。

重点重新分析“已有可用球坐标却没有事件峰”的FN，同时追踪新增FP。多尺度长窗口、大Transformer和密集TCN后置；密集输出需处理感受野边界与中心相对时间编码，不可假设与当前滑窗天然等价。

## 9 阶段三少量训练数据微调

微调从阶段一和阶段二的胜出权重开始，仅使用原训练集。建议固定约20%的训练视频作为起点，兼顾源场景组、三视角、薄框、遮挡与普通回合；PP约23–24条视频，实际数量以分层选取后的清单为准。少量指训练暴露量受限，不能借入验证或public。

事件窗口首轮预算约1500个每轮，PP和TTGames仍各占50%。PP从所选训练视频生成窗口；TTGames仍只取game_1–4的训练锚点与合法邻域。保存两源窗口清单与哈希。保留正确事件、普通背景和困难样本，避免只用错误例、正例或高置信成功例。

| 项目 | 建议起点 | 约束 |
| --- | --- | --- |
| 训练长度 | 先2–3轮，最多5轮，patience 2 | 按完整内部验证选型，不盲目续训 |
| 学习率 | 事件头3e-5；前端编码器3e-6 | 新参数分组必须在日志核对 |
| 辅助预测头 | 可从1e-5起测 | 保留球定位与桌框监督，不能只剩事件损失 |
| 损失 | Event加加权Global、Local、Table | 从预训练稳定损失尺度校准权重，记录梯度量级 |
| batch | effective 8，micro从1–2起测，AMP | 避免直接把阶段二大batch搬入在线路径 |
| 数据增强 | 已验证的温和窗口一致增强 | 使用预测ROI，保留有效性与未知mask |

所有视觉特征须在线求导，不能继续读取冻结NumPy描述符缓存。可以复用原始帧或不依赖权重的resize缓存。硬候选选择、关联和ROI坐标可停止梯度，但视觉采样及编码特征必须能将事件损失传回相应编码器；新桌框分支也要接受事件视觉梯度与桌框辅助监督。

桌框分支训练与TTGames事件监督的覆盖不同。TTGames没有可靠桌框标签的帧屏蔽Table损失，不伪造bbox；如担心微调桌框遗忘，可加入PP训练集已知桌框的小批辅助回放，计入实际样本与耗时，不能偷偷引入验证数据。

微调前做一次梯度和参数更新检查，确认没有被detach或不可微缓存截断。先保持BN运行统计固定作为小batch起点，并明确BN仿射参数是否更新。每轮监控落点、球定位、ROI含球率和桌框质量，辅助损失的占位0不能当作测得损失。

阶段二冻结版永久保留为回退候选。建议在微调前登记定位与桌框退化容限，例如各自关键指标下降不超过1个百分点；该值只是工程起点。若事件提升伴随明显定位退化或新增速度问题，回退并复查，不默认选更新模块更多的版本。

## 10 耗时估算的实测依据

以下全部来自本机5070 Ti日志，不是4090成绩。为避免续训时间截断，定位器按全部attempt逐轮elapsed_sec累计；优化器、数据量、评估频率与在线路径改变后不能直接横比。

| 历史任务 | 记录规模 | 实测时间与适用边界 |
| --- | --- | --- |
| Global fixed3 | 20轮，跨2个attempt | 逐轮累计27.18分钟，中位81.40秒每轮 |
| Local fixed3 | 20轮 | 逐轮累计68.31分钟，中位204.63秒每轮；运行墙钟约69.68分钟 |
| 冻结TCN | 28轮，已有特征缓存 | 累计93.93秒，中位3.19秒每轮；不含重提特征与完整原视频外测 |
| 历史全在线随机联合 | 完成15轮，每轮7734窗口 | 中位37.00分钟每轮，范围约34.80–38.78分钟 |
| 旧TCN完整PP验证 | 6292帧 | 77.53 FPS，约81秒；新增桌框分支后须重测 |

Global历史run.json的最后一次开始到结束约12.38分钟，但命令使用resume，实际仅覆盖后9轮；不能把12分钟当作完整20轮预算。旧全在线随机联合每轮37分钟也不能当作冻结事件头耗时。

当前在线路径包含重复窗口计算、候选处理、数据准备与同步，4090相对本机的收益不由显卡峰值算力比例决定。CPU、SSD、框架版本、batch与新增桌框网络均会改变速度。本白皮书不假设4090固定快2倍。

### 到比赛机后的首轮校准

对每条真实训练路径完成warmup，再测至少100个micro step，包含取数、前向、反向、优化器及规定的验证；记录每步时间、峰值显存与样本吞吐。微调必须用13帧真实路径，不能用单帧桌框吞吐代替。先测较小batch，再在保留显存余量的前提下增加batch。

阶段预算统一为：**训练步数乘平均每步耗时，加验证次数乘完整验证耗时，再加缓存、保存及初始化时间**。若按optimizer step计时，应把全部梯度累积micro step计入，不重复或漏算。

缓存预算为待处理帧数除以端到端提取FPS，另加索引、间隔解码和写盘成本。训练测速与推理测速分开记录；部署按SOP warmup 50次、3组各200次前向测p50和p95，再测包含解码、关联和输出的完整视频FPS。初始化与未来帧等待单列。

## 11 单张4090预算与敏感项

以下为数据已就绪、代码可运行的一轮主线预算。桌框参考640输入、每轮4000张、最多80轮；事件头预算含A至D筛选和胜者补种子；少量微调约1500窗口每轮、最多5轮。任何扩大规模都应重算。

| 任务 | 排期预算 | 估算依据或待测假设 |
| --- | --- | --- |
| 环境与小规模校准 | 0.25–0.75小时 | 含读图、前后向、恢复及真实路径测速 |
| Global 20轮 | 0.5–1小时 | 5070 Ti累计27分钟，保留迁移与评估余量 |
| Local 20轮及所需预测 | 1–2小时 | 5070 Ti累计68分钟，加数据接口与验证余量 |
| 独立桌框训练 | 1–3小时 | 320000曝光；假设40–150训练图像每秒，另加验证 |
| 一次新前端特征提取 | 0.5–1.5小时 | 当前52573帧；暂按30–100帧每秒并留I/O余量 |
| 事件头筛选与复核 | 0.5–1.5小时 | 训练本身很快，主要预算留给完整视频与错误检查 |
| 少量端到端微调 | 0.5–1.5小时 | 旧在线每轮37分钟按1500比7734缩放，再给新分支余量 |
| 最终外测与导出测速 | 0.5–1小时 | 一次锁定版本；后端不兼容的开发时间另计 |

逐项区间求和约4.75–12.25小时；加排期余量后，完整重训建议按6–13小时安排。若复用合格Global和Local，扣除两项后的和约3.25–9.25小时，安排4–10小时。不是统计置信区间，也不保证所有上界可覆盖代码故障或读盘瓶颈。

桌框吞吐40–150图像每秒是预算假设，当前没有该新模型在4090上的实测。320000次曝光的纯训练约0.59–2.22小时；1–3小时预算另假设全程验证与保存约0.3–0.8小时，上机后须单独测验证成本。若改成17281张全部每轮、80轮，曝光约138万，纯训练约2.56–9.60小时，加验证约3–11小时；整条流程可能扩大到约8–21小时。这种设置与4000张轮换方案的有效曝光量不同，不宜只按“同为80轮”比较。

微调1500比7734的线性缩放只作初始估算；新桌框分支、辅助回放、每轮固定验证成本会破坏比例。若改成全量7734窗口每轮、10轮，按旧在线路径就约6.2小时，尚未加入新分支，不能继续沿用0.5–1.5小时预算。

建议预留12–16小时连续机器窗口容纳一轮主线、补测和小范围回退；若预检预测超出窗口，先减少低优先级消融或FT轮数，保留完整验证与回退权重。人工标注、编程、网络传输和大规模超参搜索均另列。

## 12 任务顺序与两卡安排

两张4090先用于互不依赖的作业，不能因可见两卡就假定已有DDP支持。当前建议以单卡任务为基本单位，不改现有训练语义。

| 顺序 | 工作及依赖 | 完成证据 |
| --- | --- | --- |
| P0 数据冻结 | 标签复核、清单哈希、坐标与存储检查 | 新旧标签版本、patch ledger、GT overlays |
| P0 工程实现 | 独立桌框、描述符接口、缓存schema、微调子集路径 | 小批前后向、参数更新、恢复与完整视频预检 |
| P1 前端训练 | GPU0跑Global再Local；GPU1可并行桌框 | 定位与桌框精度、错误覆盖、权重哈希 |
| P1 特征生成 | 前端锁定后提取训练和验证特征 | cache_id、manifest、与在线结果一致性抽查 |
| P2 事件消融 | A至D逐步筛选；确定结构后可并行配对种子 | 固定协议完整视频结果、PR与FN/FP变化 |
| P3 少量微调 | 从冻结胜者初始化，保留阶段二候选 | 在线梯度证据、辅助任务指标与回退比较 |
| P4 发布检查 | 锁定配置后统一外测和部署测速 | 预测文件、错误索引、后端精度与完整FPS |

阶段一的球与桌框分支可并行，阶段二须等待最终前端锁定；门控与简单拼接的训练可并行，但C和D依赖前一步结果。两卡完整重训的初步墙钟可按约5–11小时预留，CPU/磁盘竞争可能抵消并行收益，不能直接把单卡总时长除以2。

工程实现需补齐四个接口：独立桌框的预测和空间特征输出；与连续追踪一致的特征缓存；事件头多分支输入与mask；少量训练数据在线微调和辅助监督。目前已有joint路径可参考，但不能直接以历史scratch命令启动本方案。新阶段参数在本文是建议规格，不是现成CLI开关。

迁移时把历史配置中的本机绝对路径改为比赛工作目录的实际路径。当前逻辑数据集入口是data/datasets/pp_ball_v2与data/datasets/openttgames_event25_v3；FrameStore相对引用随目录结构一起迁移。先检查配置解析与实际文件，再形成启动命令，避免继续指向归档里的旧ttnet/datasets路径。

比赛镜像固定torch 2.1.2、CUDA 11.8等基础组件。本地torch 2.7.1的可运行性不能代替比赛镜像验证；现有若干入口使用torch.amp.GradScaler，应适配2.1支持的torch.cuda.amp.GradScaler接口并检查恢复行为，见[PyTorch 2.1文档](https://docs.pytorch.org/docs/2.1/amp.html)。不通过升级比赛基础组件绕过兼容问题。

在新桌面ROI或采样算子确定后尽早试导出，验证实际ONNX Runtime与TensorRT 8.6路径的支持及数值偏差。参与者代码写入允许的participant区域，保持评测框架文件不变。导出成功、格式检查通过与模型精度达标是三件不同的事。

## 13 验收标准与实验记录

选型以同一40条内部验证视频的完整推理为依据，保持原帧±1、原图50px、一对一匹配、三视角宏F1。每个模型按预先固定的内部规则选择阈值，保留逐视角P/R/F1、TP/FP/FN和逐视频结果；不能仅报窗口准确率或挑选成功片段。

桌框验收同时看整体、视频均值、薄框、三视角及场景组，漏检有GT帧按失败计入相应指标；未知帧不计IoU、不凭缺标判FP。球定位报告原图球心误差、匹配覆盖、连续漏检长度与ROI含球率。没有可信无球负例时不宣称测得无球误报率。

冻结版、微调版和部署后端分别记录权重与阈值。部署速度目标是完整视频至少50 FPS，包含解码、定位、桌框、关联、事件和序列化；旧77.53 FPS不代表新增分支后仍达标。13帧中心窗口需要6帧未来上下文，叠加当前定位输入可到7原生帧前瞻，应单列等待，不能称作零延迟。

最终锁定后报告PP public及TTGames test。TTGames稀疏锚点分类F1不是连续视频落点F1；PP内部球心参考与public接触点口径分别解释。历史外部结果已用于查看，不能通过反复外测调参后仍声称独立泛化证明。

每次实验至少保存以下内容，精度与速度引用同一实际checkpoint及后端。

- 生效config、启动命令、代码commit及未提交差异快照、环境和GPU、seed、实际batch与精度。
- 数据和标签版本、split清单哈希、采样清单、增强参数、前端与缓存身份。
- best与last、权重SHA256、最佳epoch、优化器和scaler状态、逐轮耗时与显存、退出原因。
- 完整视频预测、总体及逐视频指标、阈值规则、全部错误索引，以及同时显示pred和GT的overlay。
- 部署后端、输入shape、前向p50和p95、完整FPS、初始化和未来帧等待、已知限制。

推荐的决策规则是：桌框质量先于融合；简单拼接先于复杂门控；冻结训练先于少量微调；每一步无收益就回退。最终以同协议的可复核结果选模型，不因训练更久、分支更多或更新参数更多而默认采用新版本。
