# 桌框定位精度改进方案（2026-10-18）

桌框定位作为三阶段训练中**第一阶段的独立目标**先做好，再研究桌框融合。首推使用现有YOLO工具链训练预训练单类桌框检测器，建立可靠的精度对照；共享Global FPN的空间定位头作为轻量候选。当前4×4池化后直接回归的MLP保留为旧基线。

后续更新：用户提出独立特征分支与单帧输入。新增[label随时间核查](table_label_temporal_20261018.md)支持多数片段近似静态，但发现真实镜头变化以及04_004第115帧的明确错标。先复核异常标签，独立单帧网络作为优先候选；骨干不限于YOLO，共享FPN作为可选对照，不能整段无条件固定框。

本文是现有模型/数据诊断与实施建议，未启动新模型训练、安装依赖、下载权重或修改现有模型。

## 1. 已检查到的原因

### 泛化落后，而非训练轮数不足

用现有head checkpoint在原冻结Global特征缓存上重新计算IoU：

| checkpoint | 训练帧平均IoU | 验证帧平均IoU | 验证IoU≥0.5比例 |
|---|---:|---:|---:|
| best，第4轮 | 0.7221 | 0.3875 | 38.01% |
| last，第14轮 | 0.7994 | 0.3007 | 4.21% |

训练仍在改善，但新场景显著退化。帧数不能代表场景多样性：训练17281个有标签帧来自19个场景组，验证5101个有标签帧来自另外6组。结果符合场景泛化不足；不能仅据此断定某个单独原因。

### 薄桌面严重欠覆盖

以桌框高度占画面高度小于6%定义薄框：

- 训练：480 / 17281帧，**2.78%**。
- 验证：623 / 5101帧，**12.21%**。

验证02/04组的典型高度约为画面3.7%–3.8%，在720p原图上仅约27px，在512×288输入上约11px。以宽度与高度都相同的两个27px高框为例，仅纵向偏10px，IoU就约为17/37=0.46。薄框对边缘偏移很敏感，应直接看上下边误差。

### 当前结构缺乏精细空间监督

目前先冻结仅用球定位训练的Global编码器，将32通道、144×256的FPN图池化成4×4，再让MLP输出4个坐标；没有在线图像增强，也不让桌框监督更新视觉特征。

4×4池化并不禁止连续坐标回归，但大量空间布局被提前压缩，模型缺少直接学习桌沿的机会。增加MLP层数或单纯增加epoch无法补回丢失的空间信息。

### 暂未发现坐标往返的数十像素偏差

检查全部17281/5101个有效框，从缓存归一化target反变换回原图，对原始GT的最大坐标误差均约 **0.000052px**。此外17159个训练、4947个验证相邻有标签帧中，没有相邻GT框IoU<0.5的突变。

后续原图核查已经发现明确错误标签，见[label时间变化报告](table_label_temporal_20261018.md)。坐标编码正确不等于标注正确；需要先复核异常区间，并检查桌框是否指同一张主比赛球台、是否一致只包含桌面。缺标签帧保持UNKNOWN，不自动当无桌背景，也不插值伪造GT。

完整数值、源文件哈希和可复现脚本见[审计产物](../out/results/20261018_table_accuracy_audit/audit.json)。

## 2. 主线：预训练的小型单类检测器

建议先用项目已经采用过的YOLO11工具链，选**YOLO11s预训练权重、单类主比赛球台、长边640**作为首个主配置。YOLO11支持预训练检测模型微调与导出；这只说明工具可用，不能保证本数据上的精度或比赛TensorRT8.6兼容性。[官方模型文档](https://docs.ultralytics.com/models/yolo11)

这是工程精度对照，改变了骨干、预训练与定位头，不作为纯算子消融。相较继续修补旧MLP，其优点是能直接学习空间目标、接受图像增强，并用通用检测预训练改善少场景训练。

训练数据准备：

1. 复用PP既有114/40视频及源场景组清单，不重划分、不引入public做训练。
2. 只把可靠的主球台bbox帧加入监督；缺标签不能生成空label并当确定负样本。
3. 按场景组/视频分配采样预算，时间上均匀抽帧，再补遮挡、运动模糊与光照变化帧。避免长视频的近重复帧主导训练。
4. 对薄框做分桶采样，结合适度平移、尺度、轻微透视与色彩增强。单纯重复480帧不会新增视角；增强后仍须保留有效桌面边界并同步变换bbox。
5. 首版以完整比赛画面为主，避免一开始用大量Mosaic/MixUp制造多主球台及截断语义。参数固定后再做增强对照。
6. 图中可能有背景球台。监督和输出都明确为主比赛球台；完整推理需要确定的选框规则，不能用GT挑预测框。报告原始检测失败与选错主球台的错误。

首版640输入若整体已有收益但薄框上下边仍不准，再单独测试960输入；不同时改模型规模和数据配方。将提高分辨率的精度收益与完整流水线耗时一起测。

## 3. 共享网络候选：在空间图上定位

如果希望复用球定位计算，建议直接使用池化前的FPN图，增加小型卷积桌框分支：

```text
Global encoder/FPN ── 球热图定位
                  └─ 桌框空间头 ── bbox两角热图 + 亚像素偏移
```

- 用已有bbox即可监督左上/右下两个框角，无需新增真实桌角标注。框角可能落在背景处，头部仍需要足够上下文；不能把这些bbox角当成真实桌面四角。
- 也可比较中心热图+宽高回归；只选择一种先做，不同时铺开多种结构。已有按bbox两角做目标定位的方法可参考[CornerNet原论文](https://openaccess.thecvf.com/content_ECCV_2018/html/Hei_Law_CornerNet_Detecting_Objects_ECCV_2018_paper.html)，本项目无需直接复现其全部结构。
- 先冻结骨干训练新头，再在**定位阶段**以小学习率更新部分FPN/编码器，保留球定位损失。这不接事件头，符合用户先定位后事件的路线。
- 对有效框同时使用框重叠损失、角点/偏移监督，并监控按GT高度归一化的纵向边缘误差。薄框加权应有限幅，防止极薄框或异常标签主导梯度。
- 解冻后必须检查球定位、Local ROI含球率与完整视频速度。若球定位退化，保留独立桌框检测器或进一步限制共享更新范围。

单把4×4改成8×8可作为低成本定位诊断，但仍依赖冻结的球特征，不建议将它作为唯一主线。

## 4. 框准确后再利用时序

固定机位允许多帧形成稳定估计，首版先测逐帧检测精度，再比较低频更新方案，例如每0.2–0.5秒检测、镜头内聚合可信框。该频率是待测起点，不是已验证配置。

- 用检测分数、框一致性与场景变化共同决定是否更新。检测类别分数不是经校准的IoU质量分数。
- 遮挡时可短暂沿用最近稳定框，并记录年龄；超过有效期限或镜头变化时重置、重新检测。
- 只有定位足够准确，聚合才有意义。当前正视框持续向下偏、侧视框过高，取中位数/EMA仍会保留这种系统偏差。

## 5. 评估与进入事件阶段的条件

不只报告全部帧平均IoU：

- 三视角及各源组的平均IoU；同时列帧平均与视频平均，避免22组长视频掩盖薄框场景。
- IoU≥0.5/0.75比例、漏检/主球台选错比例，以及检测器适用时的AP50/AP50–95。
- 中心与四条边的原图像素误差、中位数/P90；薄框另报按GT高度归一化的纵向误差。
- 完整视频中框的抖动、遮挡恢复、镜头切换重置，以及平均/p95计算开销。
- 缺标签帧不计IoU、不凭缺标判FP；没有输出的有GT帧应计失败，不能只统计成功匹配框。

以现有0.387为回退基线，先争取将平均IoU推进到0.70量级并改善薄框/正视偏移。这是工程目标，尚未验证或保证。桌框质量稳定后再提取桌面ROI，训练事件头，最终按用户方案用少量训练数据做端到端FT。

建议最小顺序为：**旧MLP基线 → 单类预训练检测器 → 根据残余错误决定高分辨率或共享空间头 → 准确框的时序聚合 → 事件融合**。不必将所有候选都完整训练后才做选择。
