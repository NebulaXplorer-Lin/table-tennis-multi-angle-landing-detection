# 乒乓球落点检测：论文与训练路线

检索与本地数据检查日期：2026-10-13。面向本仓库主赛题；以下推荐是结合论文与项目约束的工程判断，不是已经验证的增益。论文在其他数据集的指标不能直接当作本赛成绩。

## 1. 推荐决策

优先采用「多帧高分辨率热图定位 → 候选轨迹关联 → 触台事件识别」的分阶段方案。第一轮训练做轻量 HRNet/WASB 风格球定位；事件部分先用改进规则建立对照，补充训练集事件标注后升级小型时序卷积网络（TCN）。TrackNet 风格编码器—解码器作为速度对照。依据错误分析，再选择 ROI 精定位、运动信息或事件视觉特征。

不建议第一轮同时加入大型视频 Transformer、全套人体姿态和 3D 重建：当前数据规模、事件标签和部署链需要先建立可靠基线。

## 2. 项目证据与训练前提

本次遍历 `data/pp_train_data/annotations/**/*.json` 得到：

| 项目 | 实际检查结果 |
|---|---|
| 标注文件 | 154 |
| frames 条目 | 23,690 |
| 有 ball 标注条目的帧 | 20,846 |
| 无 ball 标注条目的帧 | 2,844，约 12.0% |
| 标注尺寸 | 119 段 1280×720；21 段 1266×720；14 段 1920×1080 |
| 类别 | ball、table、player、referee |
| 顶层字段 | video_id、video_path、frame_width、frame_height、num_frames、frames |
| 球框宽度映射到 512 宽后 | P10=1.4 px；P50=3.2 px；P90≈7.85 px |

以上是 JSON 统计，未逐视频核验实际解码尺寸、帧率、漏标率。无球标注不自动等于确定背景，需抽样区分出画、遮挡与漏标；不应把不确定遮挡帧一律强监督为全零热图。标注中未发现专门触台事件字段。

公开验证目录已有 manifest、落点 GT 和视频目录；本次未跑完整性与逐视频可读性检查。GT 包含 `valid:false` 的忽略事件，评分实现必须核对其处理规则。现有 `validate.py` 是格式校验，不是落点 F1 评分器。

赛题要求 1080p、25 fps，落点误差同时满足 ±1 帧与 50 原图像素，并做一对一匹配。精度分为三个视角 F1 各乘 25；速度分在 50 FPS 封顶。具体以本地 `TaskDescription.md` 为依据。

既有 ONNX 架构分析确认官方网络为三帧、全分辨率 HRNet 风格、SE 注意力、三通道热图。部署图约 1.293M 权重/偏置元素，但约 27.1 GMAC/窗口，参数少不代表推理轻。未确认其训练源码或论文来源，不能称作已复现 WASB/BlurBall。

## 3. 论文阅读清单

### P0：直接指导第一轮

1. **TrackNet: A Deep Learning Network for Tracking High-speed and Tiny Objects in Sports Applications（2019）**  
   [论文](https://arxiv.org/abs/1907.03698)。用连续帧生成球位置热图，是理解多帧微小球定位的基础。迁移价值是问题定义与热图监督；论文对象主要为网球，不提供本赛触台事件能力。建议先读输入、标签和热图解码。

2. **Widely Applicable Strong Baseline for Sports Ball Detection and Tracking / WASB（BMVC 2023）**  
   [论文](https://arxiv.org/abs/2311.05237) · [作者仓库](https://github.com/nttcom/WASB-SBDT)。结合高分辨率特征、位置感知训练与时序一致性推理，适合作为本项目定位主线。关注高分辨率分支、难定位样本和时序候选筛选；训练脚本与预训练权重可用性需要在实施时逐项核对，不能因存在仓库就默认可一键微调。

3. **TTNet: Real-time temporal and spatial video analysis of table tennis（CVPR Workshops 2020）**  
   [论文](https://arxiv.org/abs/2004.09927)。同时处理球定位、事件 spotting 和语义分割，是从定位走向触台识别的重要参考。OpenTTGames 是 120 fps，不能照搬到本赛 25 fps 的帧窗口长度、时间标签或原始性能。建议借鉴全局/局部定位与事件分支，按时间跨度重新选窗口。

4. **BlurBall: Joint Ball and Motion Blur Estimation for Table Tennis Ball Tracking（2025 预印本）**  
   [论文](https://arxiv.org/abs/2509.18387) · [作者项目](https://cogsys-tuebingen.github.io/blurball/)。基于 WASB 路线联合估计球位置和拖影，讨论拖影中心与前缘标注差异，并使用多帧输入与 SE 等注意力。首先借鉴标注一致性检查和模糊样本分析；本项目 bbox 不能直接提供可靠的拖影方向标签。任何重新定义球心的做法都必须与赛事落点 GT 语义对齐。

### P1：按问题升级

5. **TrackNetV3: Enhancing ShuttleCock Tracking with Augmentations and Trajectory Rectification（ACM MMAsia 2023）**  
   [作者论文 PDF](https://people.cs.nycu.edu.tw/~yushuen/data/TrackNetV3.pdf) · [作者代码](https://github.com/qaz812345/TrackNetV3)。将背景信息、mixup 与轨迹修复组合，用于羽毛球定位与遮挡处理。适合借鉴短缺口补全；乒乓球触台本身是运动突变，不能把跨触台轨迹平滑成连续弧线。背景估计还需处理镜头运动及切换。

6. **TrackNetV4: Enhancing Fast Sports Object Tracking with Motion Attention Maps（2024 预印本）**  
   [论文](https://arxiv.org/abs/2409.14543)。利用帧差、motion prompt 和运动特征融合增强 TrackNet。适合针对静态白色干扰和运动信息不足做消融；挥拍和镜头移动也会产生大帧差，不能把“运动区域”直接视作球。

7. **Deep High-Resolution Representation Learning for Human Pose Estimation（CVPR 2019）**  
   [论文与作者代码入口](https://openaccess.thecvf.com/content_CVPR_2019/html/Sun_Deep_High-Resolution_Representation_Learning_for_Human_Pose_Estimation_CVPR_2019_paper.html)。HRNet 的方法基础：保持高分辨率并反复融合并行尺度。用于理解和设计定位主干；人体姿态成绩不构成乒乓球精度证据。

### P2：研究型扩展

8. **TT3D: Table Tennis 3D Reconstruction（2025 预印本）**  
   [论文](https://arxiv.org/abs/2504.10035)。利用相机标定、运动物理和重投影误差恢复乒乓球三维轨迹。可借鉴反弹几何约束，但单目重建依赖稳定轨迹与标定，不宜作为首轮训练的基础依赖。

9. **Event Detection in Table Tennis Videos using 2D Keypoints（2026-10-06 预印本）**  
   [论文](https://arxiv.org/abs/2610.08286) · [论文给出的代码入口](https://github.com/MLCVLab/EventNet)。EventNet 用球、球桌、人体关键点序列预测距前后事件的时间。**实验目标是球拍击球，不是触台落点**；可以借鉴时间目标编码、缺失值 mask 和帧率增强，必须另用触台标签训练验证。论文标注 MMSports ’26，会期晚于本次检索日期；本次未复现其代码。

补充：TrackNetV2 是常见的多帧输入/多帧输出编码器—解码器路线，可通过上述作者论文的引用和 WASB 对照实现继续阅读。不要混淆不同作者的复现仓库、版本名和原作者实现。

## 4. 常见技术路线如何选择

| 路线 | 适用情况 | 优势 | 本项目主要代价 | 建议 |
|---|---|---|---|---|
| 单帧目标检测 + 跟踪 | 已有检测器，球较大，想快速对照 | bbox 标签直接可用 | 微小球和遮挡需要额外处理 | 对照或球桌/球员辅助 |
| TrackNet 风格多帧热图 | 想快速建立可训练球定位模型 | 输入简单、任务匹配 | 下采样可能损失细节 | 速度对照 |
| HRNet/WASB 风格热图 | 小球定位和漏检是主要瓶颈 | 保留高分辨率，接近现基线 | 高分辨率激活与计算开销 | 首选主线 |
| 全局定位 + 局部 ROI 精定位 | 缩小后球过小、触台附近误差明显 | 利用原图细节 | 需应对 ROI 漂移与重新捕获 | 第二阶段按需加 |
| 轨迹 + TCN/小型 Transformer | 球轨迹正确却触台误判 | 低维输入、开销较小 | 需要事件标签，受定位噪声影响 | 优先升级事件模块 |
| 多任务视觉事件网络 | 轨迹相似、需球拍/球桌视觉线索区分 | 利用局部外观与场景 | 标注和训练更复杂 | TCN 不足时加 |
| 单目 3D + 物理 | 视角问题突出且已有标定 | 几何一致性更强 | 25 fps、遮挡、旋转与标定误差 | 后期探索 |

“多视角”题名不表示提供同步多机位。现有接口逐视频处理；不要假设可以三角测量。球桌 bbox 也不是四个桌面角点，不能直接用来构造精确单应矩阵。桌面单应只适用于桌面上的点，不能把飞行中的球强行映射成桌面物理轨迹。

## 5. 第一轮训练建议

以下是起始实验配置，不是论文默认参数或已验证最优值。

1. **先划分，再生成窗口。** 按原比赛/相机来源分组，确认目录编号含义后再使用；不要随机拆帧或把同一回合的重叠窗口分到两边。公开 15 段验证集保留作外部评估；若反复调参，应另有保留集估计泛化。
2. **数据核验。** 逐视频确认 fps、实际尺寸、0 基帧号；抽样检查球框中心、拖影和缺标。1266×720 不可按 1280 硬编码。记录每次缩放、裁剪、padding 的逆变换。
3. **首个定位模型。** 三帧 RGB 输入，512×288，轻量高分辨率网络，先预测中心帧热图。三帧三输出作为下一项消融；这属于新训练模型，部署封装需在 participant 代码区适配。
4. **监督与损失。** 有效球框中心生成高斯热图，sigma 从输入尺度约 1.5–2.5 px 的小范围试验；起点为前景/背景分别归一化的加权热图 MSE。与 BCE 类损失做单独对照；不直接堆所有损失。不确定缺标采用 ignore mask，确定无球样本才用全零目标。
5. **优化起点。** AdamW，学习率约 3e-4、weight decay 1e-4；AMP，先试 micro-batch 2–4，显存允许再增大。小批量时注意 BN 统计，梯度累积不会改善单步 BN 的统计质量。先用少数片段检查能否过拟合，再启动完整训练，用验证曲线决定训练长度。
6. **增强。** 窗口内一致的几何变换，适度亮度/颜色、压缩、模糊和尺度变化；避免逐帧随机裁剪破坏真实运动。裁掉球后同步更改标签。跨帧一致的光度增强可先作为起点，复杂增强逐项验证。
7. **解码。** 从热图提取局部峰/连通域候选，用时序距离与置信度关联，拒绝全图多个峰一起求质心。速度约束按实际帧间隔归一化；缺口较大时断轨并重捕获。
8. **事件对照。** 固定相同落点规则比较定位模型，避免同时改两层导致无法归因。另将 GT 球心输入事件规则进行诊断：若轨迹理想时仍漏检/误判，优先投资事件模型，而非继续放大定位网络。

本机记录为 RTX 5070 Ti 16GB。上述 batch 是待测起点，不是显存承诺。训练环境与固定评测环境不同，早期即做 ONNX/目标 TensorRT 的小规模导出和数值对齐；不修改赛事 core 或升级评测基础依赖。

## 6. 触台事件标签与时序模型

现有训练 bbox 可直接训练定位，不能直接当成触台标签。建议在训练回合上生成轨迹可视化与候选时刻，人工复核触台/击拍/不确定事件，并检查候选之外的全片以补漏，覆盖三个视角、遮挡和快速连续触台。规则生成的数据只能称为伪标签；保留独立人工事件验证子集。

TCN 第一版可使用约 9–15 帧窗口，输入归一化 x/y、置信度、可见性 mask、按 Δt 计算的速度/加速度以及相对桌框位置，预测中心帧触台概率。该窗口是针对 25 fps 的待验证起点；输出时延与事件帧号需明确区分。标注不足时从二分类开始，不凭空生成击拍类别。

训练时混合带噪声/缺失的 GT 轨迹与折外预测轨迹，避免只在完美轨迹上学习、推理时失效。事件目标可采用时间软标签或比较 time-to-event 回归，但评分仍须按真实 ±1 帧规则执行。触台前后分段拟合，避免全段平滑抹掉反弹。

## 7. 升级顺序与止损依据

| 阶段 | 只改变什么 | 判断依据 |
|---|---|---|
| E0 | 官方 ONNX + 原规则，完整跑通评分与计时 | 本地真实基线，不用文档 F1 代替 |
| E1 | 新训练三帧热图网络，规则固定 | 分组留出集球定位与最终落点是否同时改善 |
| E2 | 多峰候选关联、断轨处理、事件附近短缺口策略 | 误检、断轨和重复落点是否减少 |
| E3 | 补触台标签，规则换 TCN | 球已找对但触台时刻错的样本是否改善 |
| E4a | 定位仍不足：640×360 或全局+ROI | 额外精度是否值得耗时；640×360 像素量为 512×288 的约 1.56 倍 |
| E4b | 白色干扰/模糊突出：运动特征或 BlurBall 思路 | 对应困难子集提升且普通场景不退化 |
| E4c | 事件仍不足：局部视觉特征/桌角点上下文 | 区分触台与击拍的增益能否覆盖复杂度 |
| E5 | 导出 FP16、缓存预处理、流式后处理 | 在固定评测栈中验证数值、端到端 FPS 和稳定性 |

每轮记录：定位 Recall/Precision、位置误差分位数、无球误报、触台附近定位召回；事件的 TP/FP/FN、重复事件、帧误差、空间误差；各视角 F1；端到端 FPS、显存和模型大小。检查首尾帧和 ignore 事件处理。一对一匹配与忽略区域的具体优先级若未获官方 scorer，必须注明为本地近似口径。

总分目标不是最低热图 loss，也不是最高单模型 FPS。三个视角各提升 0.01 F1，精度分共增加 0.75；超过 50 FPS 后继续提速不增加速度分，但可为更好的定位/事件模块留下预算。先用真实错误分布决定下一项实验。
